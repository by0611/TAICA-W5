# 研究所報名資訊整合網站

**研途 Grad Atlas**｜研究所招生資料查詢與申請準備工具

| 項目 | 內容 |
| --- | --- |
| 文件用途 | 專案說明與完整需求規格 |
| 規格版本 | V0.1 |
| 單檔程式版本 | V1.0 |
| 更新日期 | 2026-10-19 |
| 介面語言 | 繁體中文 |
| 預設時區 | Asia/Taipei |

集中整理不同研究所的報名管道、申請資格、應繳文件、各項截止時間、費用及繳款方式。使用者可搜尋、篩選研究所，點選招生方案後查閱完整資料，並記錄自己的準備進度。

> 預載學校、招生條件、費用與時程均為虛構示範，不可據此實際報名或付款。真實招生資料由使用者自行提供、整理及確認；系統不以自動爬取官方網站為必要條件。

## 快速開始

1. 下載本專案的 `index.html`。
2. 使用 Chrome 或 Edge 直接開啟 `index.html`。
3. 在「探索研究所」搜尋學校、研究所、組別或領域，使用年度及招生管道等條件篩選。
4. 點選招生方案查看時程、文件、繳費資訊與聯絡方式。
5. 使用「本機資料工作區」新增自己的資料，或匯入 CSV／JSON。
6. 定期匯出 JSON 完整備份，保留招生資料、收藏、個人進度及最近異動紀錄。

CSS 與 JavaScript 均內嵌於 HTML，無外部套件依賴，不需安裝開發工具或啟動伺服器。外部報名入口與附件連結仍需連線。

### 本機資料保存

- 使用瀏覽器 `localStorage` 儲存，不會自動同步到 GitHub、其他瀏覽器或其他電腦。
- 搬動 HTML、更換瀏覽器、清除瀏覽資料或使用隱私模式時，資料可能無法保留，請先匯出 JSON 備份。
- 瀏覽器無法使用本機儲存時，頁面會顯示提示；此時變更只保留於本次視窗。
- JSON 完整備份還原會取代目前資料；CSV 或 JSON 招生資料陣列依識別碼合併。
- CSV 的 `_json` 欄位保存時程、文件與支付等結構化資料，須保留合法 JSON 格式。
- 網址中的方案識別碼只能開啟目前瀏覽器已有的資料，不會將本機資料自動分享給其他人。

## 1. 產品目標

建立一個集中查詢研究所招生與報名資訊的網站。使用者可搜尋學校或研究所、篩選招生條件，點選清單後，在同一個詳細頁查到報名管道、應繳資料、各項截止時間、費用與繳款方式，減少在多份資料間反覆查找。

第一版的核心是「可搜尋的研究所清單」與「完整的招生資料頁」。資料由管理者整理維護，支援手動輸入及表格匯入；不以自動蒐集網站資料為必要條件。

## 2. 規劃前提與範圍

| 項目 | 規劃內容 |
| --- | --- |
| 適用範圍 | 暫以臺灣研究所招生為主；保留擴充其他地區的欄位。 |
| 招生類型 | 可記錄碩士班、博士班、在職專班，以及甄試、考試、其他管道。實際首批範圍待定。 |
| 資料單位 | 一筆招生方案＝研究所 × 入學學年度及學期 × 學位班別 × 招生管道 × 組別 × 梯次。 |

## 3. 主要操作流程

進入首頁 → 輸入研究所或學校關鍵字 → 篩選年度與管道 → 點選招生方案 → 查閱資料、期限及繳款說明 → 返回原搜尋結果。

同一研究所可先顯示為一張卡片，再列出其招生方案；從卡片直接點選方案進入詳細頁。若只點研究所名稱，先呈現該所的方案清單，避免直接帶入錯誤年度或管道。

## 4. 使用者與頁面架構

### 使用者角色

| 角色 | 可使用功能 |
| --- | --- |
| 一般訪客 | 搜尋、篩選、查看招生資訊、開啟報名連結、下載公開附件、列印資料頁。 |
| 資料編輯者 | 登入後新增及修改草稿、匯入資料、預覽、送交發布。 |
| 管理者 | 具編輯者功能，另可發布、撤回、封存、管理帳號及查看異動紀錄。 |

個人申請進度與多使用者會員功能列為後續擴充；若只由一人維護，編輯與發布權限可由同一管理者持有。

### 頁面清單

| 頁面 | 必要區塊與操作 |
| --- | --- |
| 首頁與研究所清單 | 搜尋框、年度及招生篩選、結果筆數、排序、研究所卡片、招生方案入口。 |
| 研究所方案清單 | 學校與研究所名稱、各年度／管道／組別方案、方案狀態、返回結果。 |
| 招生詳細頁 | 方案識別、關鍵期限、報名步驟、資格、繳交資料、繳費資訊、其他時程、聯絡與附件。 |
| 管理清單 | 關鍵字查詢、草稿／已發布／已封存篩選、缺漏檢查、匯入、編輯。 |
| 資料編輯與預覽 | 分區表單、欄位提示、重複檢查、變更摘要、前台預覽、發布操作。 |
| 異動紀錄與帳號 | 變更者、時間、前後版本、還原入口、管理者及編輯者權限。 |

### 清單與詳細頁的互動

- 桌面可採左側篩選、右側結果；手機採上方搜尋、可收合篩選與單欄結果。

- 每筆方案有固定網址，可直接分享或重新整理；網址帶穩定識別碼，名稱變更不產生新的招生資料。

- 返回清單時保留搜尋字、篩選、排序與所在頁次；重新整理可還原網址中的查詢條件。

- 詳細頁以分區與錨點快速導覽，重要截止時間置頂；避免必須切換多個分頁才能看完整資訊。

## 5. 搜尋與清單功能規格

| 編號 | 功能 | 行為規則 |
| --- | --- | --- |
| F01 | 關鍵字搜尋 | 搜尋學校全名、簡稱、研究所名稱、組別及人工設定標籤；支援部分文字比對。 |
| F02 | 文字處理 | 去除首尾空白；英文字母不分大小寫；支援全半形正規化。多個關鍵字採全部符合。 |
| F03 | 別名對照 | 以管理者維護的別名表處理常用簡稱及臺／台等寫法，不自動推測名稱或合併研究所。 |
| F04 | 條件篩選 | 入學學年度、入學學期、學校、地區、學位班別、招生管道、領域、組別、報名狀態。 |
| F05 | 篩選邏輯 | 不同篩選欄位取交集；同欄位多選取聯集。可一鍵清除，並顯示目前套用條件。 |
| F06 | 排序 | 預設精確名稱匹配優先，其次部分匹配，再依學校／所名；可改為截止日近到遠或最近更新。 |
| F07 | 結果呈現 | 顯示符合的研究所數及招生方案數；每頁預設 20 個研究所，可調整為 50 個。 |
| F08 | 結果狀態 | 分別呈現載入中、沒有符合結果、資料載入失敗與重試；不把讀取失敗當成零筆資料。 |

### 卡片內容

卡片包含學校、研究所、地區及領域；其下列出符合條件的方案。每個方案顯示入學年度及學期、學位班別、管道、組別／梯次、報名起訖、最近尚未到期的重要期限、資料狀態及最後更新時間。未設定的日期明確顯示「尚未提供」。

### 搜尋邊界與排序

- 未指定學年度時可顯示跨年度結果，但每個方案必須標明年度；不自動把上一年度的時程當成本年度。

- 首頁預設排除已封存資料；可主動切換歷年資料。年度篩選預設值由管理者設定，畫面需明示。

- 截止日排序以報名截止為準；已截止與未知日期放在尚未截止方案之後，同值依名稱及識別碼穩定排序。

- 沒有結果時保留已輸入文字，提供清除篩選及調整關鍵字入口；首版不承諾拼字修正或語意搜尋。

## 6. 招生詳細頁欄位規格

下表為資料頁的完整欄位範圍。除身分識別與發布必要欄位外，其餘可標示「已提供」「待補」「不適用」，並保留補充說明，不用空白代表不同意義。

| 分區 | 欄位內容 |
| --- | --- |
| 方案識別 | 學校全名／簡稱、研究所全名、學院、校區／地區、領域、入學學年度、學期、學位班別、管道、組別、梯次。 |
| 招生概要 | 招生名額、身分別配額、修業年限、上課方式與地點、授課語言、特色及其他備註；名額可標示尚未提供。 |
| 報名管道 | 線上報名入口、操作說明、其他報名方式、報名步驟順序、帳號建立需求、報名完成條件及查詢方式。 |
| 資格條件 | 學歷／科系限制、應屆生或同等學力條件、工作年資、語言或其他門檻、不同身分規定及例外說明。 |
| 審查與考試 | 書面審查／筆試／面試項目、各項比重、考科、考試與面試時間地點、通知方式、線上面試說明。 |
| 應繳資料 | 文件清單、必繳或條件必繳、份數、格式、大小／頁數、簽章、提交方式、對應期限及附件範本。 |
| 重要時程 | 報名、繳費、上傳、推薦信、郵寄、補件、考試、面試、放榜、正備取報到與遞補等事件。 |
| 費用與繳款 | 報名費、幣別、減免條件、付款方式、銀行／代碼／戶名／帳號類型、取得個人帳號方式、繳費期限、查核及退費說明。 |
| 附件與聯絡 | 簡章或整理文件、表單範本、附件版本／適用年度、單位、電話、分機、Email、地址、服務時間。 |
| 資料維護資訊 | 資料提供方式與出處備註、適用年度、最後更新、最後確認、缺漏項目及變更摘要。來源連結為選填。 |

### 內容顯示規則

先呈現方案識別與關鍵期限，再依報名步驟、文件、繳款、資格及其他資訊展開。每區可使用快速跳轉；有缺漏時標示具體項目，仍可閱讀其餘內容。欄位支援必要的換行與條列，不接受任意執行的 HTML。

「報名入口」與「查詢／繳款入口」分開命名。無連結時顯示未提供及可用說明，不產生假連結。外部連結另開視窗並有文字標示；附件顯示格式、大小與版本。

## 7. 繳交資料與報名步驟

### 每份文件的資料結構

| 欄位 | 規格 |
| --- | --- |
| 名稱與分類 | 例如成績單、自傳、研究計畫、推薦信；允許管理者新增文件類型。 |
| 必要性與條件 | 必繳、選繳、符合特定條件才繳；條件以明確文字呈現。 |
| 數量與限制 | 份數、正本／影本、語言、頁數、檔案類型、單檔及總容量限制；無資料時不自行設定。 |
| 製作要求 | 簽名、蓋章、用印、合併檔案、命名規則、有效期間與其他格式要求。 |
| 提交方式 | 線上上傳、郵寄、現場、Email、由推薦人提交；同一文件可有多個提交要求。 |
| 期限與目的地 | 關聯具體時程事件；填寫入口、收件人、地址或其他提交說明。 |
| 範本與備註 | 範本附件、填寫說明、替代文件、補件規則、其他依身分適用事項。 |

### 文件與時程的關聯

共用的上傳期限可關聯多份文件；推薦信、紙本文件或特殊項目可以有獨立期限。若需同時上傳及寄送，兩個要求分別顯示。每份文件清楚標示「誰提交」「如何提交」「何時完成」，推薦人提交不得顯示為考生上傳。

### 報名步驟的規則

管理者設定有順序的步驟，每步包含名稱、操作說明、入口、關聯文件與期限，以及先決條件。例如先建立帳號、填表、取得繳費資料、繳費、上傳文件，最後確認送出；實際順序依該方案設定，不套用單一固定流程。

- 方案可設定最後完成條件，例如「表單送出且付款查核完成」；第一版僅展示條件，不自動判定考生完成。

- 列印頁保留全部文件、條件、各別期限及繳款說明，隱藏網站導覽及管理按鈕。

- 第一版附件僅存放公開範本或招生資料，不蒐集考生身分證、成績單等個人申請文件。

- 後續若加入個人清單，可分為未準備、準備中、已備妥、已提交；勾選僅代表自我紀錄，與實際受理狀態分開。

### 時程事件欄位

| 欄位 | 規格 |

| 事件 | 類型、名稱、適用方案／文件、開始日期時間、結束日期時間、地點／連結及備註。 |
| 日期精度 | 區分有確切時間、只有日期、期間、待公告及不適用。保留原文字說明。 |
| 時區與顯示 | 臺灣方案預設 Asia/Taipei；顯示西元日期及 24 小時制。民國年輸入可轉換但需預覽確認。 |
| 截止依據 | 線上送出、付款完成、入帳、郵戳、必須送達或其他條件；郵寄日期不可只寫截止而省略依據。 |
| 延長與異動 | 保留原期限及新期限，記錄變更原因與時間；前台以有效期限為主，提供異動摘要。 |

### 自動狀態規則

| 狀態 | 判定與畫面行為 |
| --- | --- |
| 待補時程 | 開始或截止資訊不足以判定時顯示時程待確認；不可因空白標成已截止。 |
| 尚未開始 | 有足夠時程，且目前時間早於報名開始。 |
| 報名中 | 目前已達開始，且未超過確切截止；開始不明但截止未到時僅顯示截止資訊及待確認。 |
| 即將截止 | 確切截止距目前 7 天內；以「7 天內截止」顯示，可另顯示剩餘完整日／時。 |
| 已截止 | 已超過確切報名截止；截止時刻本身仍視為可提交，超過後改為已截止。 |
| 停止招生／取消 | 由管理者明確設定，優先於自動報名狀態；保留原因。 |

### 日期不完整的處理

若只知道截止日期，不補成 23:59。截止日當天顯示「今日截止，時間待確認」，從次日起可顯示已過截止日期。開始日只有日期時，當天顯示「今日開始，時間待確認」。此類情況不做精確倒數。

報名、繳費、上傳與郵寄各自判定，不因報名尚未截止就顯示所有項目可辦理。「最近重要期限」選取尚未到期的事件；沒有未來事件則顯示無後續已知期限。學年度與實際事件年份分開儲存，允許跨年。

## 9. 費用與繳款資訊

### 繳款欄位與帳號類型

| 欄位 | 內容與規則 |
| --- | --- |
| 費用項目 | 報名費或其他費用、金額、幣別、適用身分、減免條件與申請方式；未知金額不顯示為 0。 |
| 付款方式 | ATM、銀行轉帳、臨櫃、信用卡、超商或其他方式，可多選並分別說明。 |
| 銀行資料 | 銀行名稱、銀行代碼、分行、戶名；依付款方式決定哪些欄位適用。 |
| 共用帳號 | 可儲存及顯示管理者確認適用的完整帳號、年度、用途、匯款備註與取得依據。 |
| 個人虛擬帳號 | 前台顯示「須至報名系統取得個人帳號」與取得步驟／入口；不放置範例帳號供直接付款。 |
| 其他支付資訊 | 超商代碼、條碼或信用卡入口以取得方式及操作說明呈現；不預設所有人可共用。 |
| 期限與完成依據 | 關聯繳費截止事件；說明以交易、入帳或系統查核為準，以及例假日、入帳時間等要求。 |
| 查核與退費 | 查詢入口、預估查核時間、交易失敗處理、退費條件、洽詢單位與備註。 |

### 顯示與輸入規則

- 銀行代碼及帳號以字串儲存，保留前導零；不以數值欄位或試算表自動轉成科學記號。

- 只有被設定為共用且已確認的帳號可提供複製按鈕；旁邊列出適用方案、年度與最後確認時間。

- 帳號尚未確認、只提供取得方式、付款方式不適用帳號時，分別顯示對應狀態，不能共用同一個空白提示。

- 帳號或銀行資料異動需重新確認，寫入異動紀錄；未確認版本不發布可供直接付款的帳號。

- 共用費用資訊可重複使用，但管理者必須確認適用方案；不得因同校就自動沿用上一年度帳號。

### 第一版付款功能範圍

網站呈現繳款資訊與外部入口，不代收費用、不執行銀行交易、不保管信用卡資料，也不宣稱付款已受理。後續若加入個人繳費紀錄，個人虛擬帳號僅能由本人查看，並與公開招生資料分開存放。

## 10. 資料維護與發布流程

### 資料建立與生命週期

建立草稿 → 填寫／匯入 → 缺漏及格式檢查 → 前台預覽 → 發布 → 更新或撤回 → 歷年封存。草稿只供有權限者查看；訪客只讀取已發布版本。封存與報名已截止分開，截止不自動刪除資料。

| 功能 | 要求 |
| --- | --- |
| 手動維護 | 依學校、研究所及招生方案分層編輯；可複製舊年度作草稿，但期限、金額、帳號與確認狀態須重新填寫或確認。 |
| 表格匯入 | 提供 CSV 範本與欄位說明；上傳後先預覽新增／更新／錯誤筆數，確認後才寫入。 |
| 重複與更新 | 以穩定識別碼更新；新資料按方案組合檢查重複。疑似重複由管理者決定，不自動覆蓋。 |
| 錯誤處理 | 列出行號、欄位、原值與原因；整批驗證通過才執行匯入。匯入失敗保留原資料。 |
| 發布門檻 | 必須有方案完整識別、有效報名方式或待補說明、來源／提供方式備註與確認狀態。缺漏項目要明示，不能用假資料補齊。 |
| 關鍵資料檢查 | 開始晚於結束、負數金額、非法網址、相同方案、年度不明均阻擋；缺精確時間或未填名額可警示後發布。 |
| 版本與復原 | 保留操作人、時間、變更原因、前後值及發布版本。還原建立新版本，不刪除歷史。 |
| 附件管理 | 限制允許格式與檔案大小，保留原檔名、版本及適用範圍；替換後更新附件時間，不影響其他方案。 |

### 資料來源與確認狀態

支援人工整理、使用者提供、既有表格或附件。來源名稱、檔名、頁碼或備註可記錄；網站來源連結為選填，不要求每筆資料都依賴官方網站。資料確認與內容完整度分開，最後修改時間也不等於最後確認時間。

發布後若修改截止時間、文件要求或繳款資訊，必須填變更摘要。沒有新年度資料時顯示「新年度尚未提供」，保留舊年度原標示。首版不排程爬取網站、不自動生成真實報名數據。

## 11. 資料結構與品質規格

### 建議的邏輯資料模型

| 資料實體 | 關係與用途 |
| --- | --- |
| 學校 School | 一校對多研究所；儲存全名、簡稱、地區、校區及別名。 |
| 研究所 Program | 隸屬學校；儲存名稱、學院、領域與別名；名稱異動保留穩定識別。 |
| 招生方案 Offering | 隸屬研究所；存放年度／學期／班別／管道／組別／梯次、資格、名額及發布狀態。 |
| 時程 Event | 一方案對多事件；記錄日期精度、時區、截止依據與異動。 |
| 文件 Requirement | 一方案對多文件；文件可關聯多筆提交方式與事件，避免一文件只能有單一期限。 |
| 步驟 Step | 一方案對多步驟；具順序、先決條件、入口及文件／時程關聯。 |
| 費用與支付 Payment | 一方案對多費用／付款方式；共用帳號及個人取得方式分開表達。 |
| 附件與聯絡 | 可由多方案引用；包含適用範圍、檔案資訊及聯絡單位。 |
| 來源與版本 | 對應方案或特定欄位；保存提供方式、確認狀態、發布版本及操作紀錄。 |
| 管理帳號 | 登入與權限控制；個人收藏與進度若擴充，另建使用者專屬資料。 |

### 欄位與驗證原則

- 欄位值與狀態分開儲存，例如金額未知、不適用、尚待公告都不以 0 代替；前台不得出現 undefined 或空白表格。

- 日期精度、時區及原始說明一併保存；入學學年度不能直接當作報名事件年份。

- 多管道、多組別、多輪報名使用獨立方案，不把所有資訊堆進同一個備註欄。共用資料需明確關聯。

- 文件與付款資訊的已確認狀態，需附確認者及時間；部分欄位更新不應覆蓋其餘欄位的確認紀錄。

- 前台資料與管理寫入操作分開授權；穩定識別碼不可取代權限檢查。實作資料庫與框架留待開發階段選定。

### 下次討論需要決定的事項

1. 使用對象：先供自己查閱，或開放其他考生使用。
2. 資料範圍：首批學校／研究所、入學學年度、碩士／博士及甄試／考試。
3. 資料提供：由誰整理、採用何種表格／附件，以及是否需要多人維護。
4. 首版功能：是否將收藏、個人進度或提醒提前納入。
5. 上線條件：預算、預期使用人數、網域、維護頻率與資料更新責任。

建議先確認首批研究所與資料欄位，再以少量示範資料驗證搜尋及詳細頁。示範資料須明確標示，不使用虛構的真實招生日期或可付款帳號。
